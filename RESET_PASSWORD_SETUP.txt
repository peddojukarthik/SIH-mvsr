SIH Secure DMS — Password Reset Setup

FILES IN THIS PATCH
1. invite_backend.py
   - Adds /password-reset/request
   - Adds /password-reset/confirm
   - Stores only a SHA-256 hash of the emailed reset code
   - Code expires after 10 minutes
   - Maximum 5 incorrect attempts
   - Previous pending codes are revoked when a new code is requested
   - Successful reset bcrypt-hashes the new password
   - All existing sessions are invalidated after a password reset
   - Local startup also falls back to allaince.env when .env is absent

2. login.html
   - Adds Forgot Password to the existing login page
   - Employee ID -> email code -> new password -> login
   - Automatically uses local backend on localhost and Render backend when deployed

3. password_reset_migration.sql
   - Creates password_reset_tokens
   - Repairs the known Secunderabad Police Head demo account with Demo@1234
   - Contains an OPTIONAL commented query to repair all demo Department Head accounts

IMPORTANT ORDER
1. Run password_reset_migration.sql in Supabase SQL Editor.
2. Replace your current invite_backend.py with this patched file.
3. Replace your current login.html with this patched file.
4. Make sure Render has RESEND_API_KEY and RESEND_FROM_EMAIL configured.
5. Deploy/restart the backend.
6. Open login.html and test Forgot Password.

DEMO HEAD

SECURITY
- Do not put plaintext passwords in the database.
- Do not commit .env or allaince.env to GitHub.
- bcrypt hashes will intentionally differ even when the same password is used because bcrypt uses a random salt. Login/reset verification uses bcrypt.checkpw().
